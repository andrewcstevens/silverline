# Silverline Voice System

## Voice thesis

Silverline speaks like a precise field instrument: observant, composed, market-literate, and concise. It names conditions rather than promising outcomes.

The voice is **quietly elevated, never theatrically financial**.

## Core characteristics

| Characteristic | Do | Do not |
|---|---|---|
| Precise | Name the source, time, state, and limitation | Hide mechanics behind mystique |
| Calm | Describe observed conditions | Create urgency or FOMO |
| Market-literate | Use correct plain terms for quote, spread, price, and evidence | Use jargon as status decoration |
| Proprietary | Use approved Silverline terms consistently | Invent a new term for every feature |
| Brief | Let numbers carry detail | Write promotional paragraphs around a price |
| Honest | State uncertainty and proxy limitations | Imply certainty, advice, or execution |

## The three-layer model

Use layered disclosure for proprietary/technical content.

```text
QUOTE SURFACE
Kalshi reference quote
YES 54¢ · NO 46¢ · Updated 11 sec ago
Reference only. Manual decision required.
```

- Headline: proprietary instrument label.
- Subhead: plain factual meaning.
- Detail: values, source/freshness, limitation, and action context.

## Sentence rules

- Prefer observed conditions over forecasts: `Historical alignment is present`, not `BTC will rise`.
- Prefer qualified facts over absolute claims: `At this reference price`, not `This is profitable`.
- Prefer user agency: `Inspect entry`, not `Take trade`.
- Prefer useful restraint: `The direction may hold. The price does not.`
- Prefer short sentences with one claim each.
- Define an unfamiliar term at first meaningful use.
- Put material qualifications close to the claim they qualify.

## Approved product voice examples

| Moment | Approved copy |
|---|---|
| No qualifying conditions | `The Field is quiet.` |
| Explanation | `No qualifying price-adjusted historical alignment is currently available.` |
| Intermediate state | `Some conditions align. Price and evidence still require review.` |
| Strongest qualifying state | `Golden Window: the best currently observed alignment under PRE rules.` |
| Golden Window qualifier | `Historical and price-dependent. Not a guarantee.` |
| Price invalidation | `The historical direction may hold. The displayed price removes the edge.` |
| Stale reference | `Reference is delayed. Do not treat this as a current read.` |
| Historical result | `Recorded historical outcome.` |
| Manual action | `Inspect entry` / `Review evidence` / `Compare price` |
| Source label | `Coinbase BTC-USD spot proxy — not prediction-market settlement data.` |

## Numbers and evidence

When relevant, show the number first and its meaning beside it:

```text
Historical observed rate  54.8%
Evidence range            49.2%–60.3% (95% CI)
Observation count         n = 438 intervals
Model through             2026-08-30
```

Do not write a historical rate as `chance of winning`, `predicted probability`, or `confidence that this contract resolves`.

## Quote language

Use only source-explicit, freshness-aware quote language:

```text
QUOTE SURFACE
Kalshi reference quote
YES 54¢ · NO 46¢
Updated 11 sec ago
Reference only. Manual decision required.
```

If the reference is stale, delayed, unavailable, fixture-only, or replayed, say so directly in the same visual context.

## Voice in risk and compliance

Do not exile caveats to a legal footer. Use direct, dignified language:

`Silverline is a historical backtest and probability-context tool, not financial advice.`

`At a 15-minute scale, BTC is close to a random walk. Slot effects can be weak, regime-dependent, and statistically fragile.`

`Past performance does not predict future results.`

## Approved actions

- Inspect entry
- Review evidence
- Compare price
- View methodology
- Check source
- Review replay
- Log a manual bet
- Wait for a current reference

## Avoid actions

- Buy now
- Take trade
- Enter position
- Lock it in
- Claim window
- Catch the move
- Beat the market
- Execute

## Copy QA questions

Before approval, ask:

1. Could a user reasonably read this as a guarantee, forecast, trade instruction, or financial advice?
2. Does it label historical, replay, fixture, proxy, delayed, stale, or live state accurately?
3. Does it name the external source when relevant?
4. Is the qualification adjacent to the claim?
5. Can a user understand it quickly on a mobile screen?
6. Does it match an approved registry term?
